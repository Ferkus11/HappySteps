# Демо-данные «Happy Steps»

Демо-сад нужен для показа платформы: в нём живые цифры за последние три месяца, есть долги, очереди и заявки. Каждая роль сразу видит заполненный экран.

## Как загрузить

```bash
npm run db:seed          # без --e2e: создаёт демо-сад «Happy Steps»
```

- Скрипт `scripts/seed/demo.ts` работает около 20 секунд. Ему нужны `NEXT_PUBLIC_SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` из `.env.local`.
- Повторный запуск безопасен. Сначала удаляются только демо-сад (slug `happy-steps`), его файлы в Storage и демо-аккаунты (телефоны `+77070…`), потом всё создаётся заново. Пользователи и сады e2e (`+7701000…`, `+7702000…`) не затрагиваются, поэтому демо и e2e могут жить в одной базе.
- История строится от «сегодня» по времени Алматы. **Перезапускайте сид в день показа**, иначе отметки «сегодня», свежие чеки и ближайшие события устареют.
- `npm run db:seed -- --e2e` по-прежнему создаёт фикстуры e2e и демо не трогает.

## Пароль

У всех демо-аккаунтов один пароль. Скрипт выбирает его так:

1. Если задана переменная `DEMO_PASSWORD` (не короче 8 символов), берётся она.
2. Если её нет и Supabase локальный (`127.0.0.1`/`localhost`), берётся пароль по умолчанию **`HappySteps2026`**.
3. Если стенд не локальный, генерируется случайный пароль. Скрипт печатает его в конце вывода, в коде он не хранится.

На общем или публичном стенде всегда задавайте свой пароль: `DEMO_PASSWORD='…' npm run db:seed`.

## Что внутри

- **Сад**: «Happy Steps», Алматы, часовой пояс Asia/Almaty, язык ru. Заполнены реквизиты (Kaspi, IBAN), настройки питания и тариф Pro.
- **Группы (6)**: «Балапан» (ясельная), «Ботақан», «Күншуақ», «Жұлдыз», «Радуга», «Зерде» (предшкольная). У каждой свой цвет, вместимость и тариф от 80 000 до 95 000 ₸.
- **Дети**: 118 в саду и 11 в архиве (выпуск в школу, переезд, другой сад, по семейным обстоятельствам, по здоровью). Казахские и русские ФИО, аллергии и медицинские заметки. Есть переводы между группами и приход в середине месяца.
- **Родители**: 157 аккаунтов. Есть семьи с несколькими детьми (скидка на второго ребёнка) и семьи, где в приложении оба родителя.
- **Сотрудники**: 24 человека во всех ролях плюс суперадмин. Один сотрудник уволен. Есть графики, отпуска, больничные, прогул и переносы смен.
- **Рабочее время** за 3 месяца: опоздания, «забыл отметиться», дни, закрытые автоматически, ручные правки заведующей (все с записями в журнале действий).
- **Посещаемость** за 3 месяца: около 7,4 тыс. отметок, 86–92% в месяц. Причины отсутствия и сообщения родителей, праздники РК и санитарный день.
- **Оплата**: около 470 счетов (начислены через `invoices_accrue`) и около 460 чеков. Есть оплаченные, частично оплаченные, отклонённые с повторной загрузкой, ожидающие проверки, корректировки и несколько должников. Распределение по FIFO согласовано с БД.
- **Кружки (5)**: «Шахматы» (мест нет, очередь из 3), «Рисование», «Английский язык», «Ритмика и танцы», «Футбол». Есть заявки на рассмотрении и история (ушёл, исключён, отклонён).
- **Лист ожидания**: 12 заявок. 5 новых, 3 «связались» с комментариями, 2 отказа, 2 принятых (дети уже в «Балапан»).
- **Остальное**:
  - 10 объявлений, часть важных, с прочтениями и вложениями.
  - 12 событий, прошедших и будущих.
  - Чаты групп, чат сотрудников и личные переписки с отметками о прочтении.
  - Документы детей и сотрудников, часть истекает в ближайшие недели (файлы лежат в приватных бакетах).
  - Меню, дни рождения на этой неделе и около 900 уведомлений в колокольчике.

## Проверка

```bash
npm run db:seed
DEMO=1 E2E_PORT=3110 npx playwright test --project=e2e tests/e2e/90-demo.spec.ts
DEMO=1 E2E_PORT=3110 npx playwright test --project=screens tests/screens/stage7-demo.spec.ts   # скриншоты в screenshots/stage7/demo-*.png
```

Без `DEMO=1` эти спеки пропускаются, обычный прогон `npm run e2e` демо не требует.
