4. **После каждого этапа — проверочный цикл:** `typecheck` → `lint` → unit-тесты → тесты RLS → e2e smoke (Playwright) → `build`. Всё зелёное — коммит с понятным сообщением. Что-то красное — чинишь до зелёного, не идёшь дальше.

6. **Веди `PROGRESS.md`:** что готово, что в работе, известные проблемы. Это главный способ для человека понять состояние проекта.

## 1. Продукт в двух словах

Мультиарендная (SaaS) веб-платформа + PWA для частных детских садов Казахстана. Собирает ежедневную жизнь сада в одном месте: дети и группы, посещаемость, учёт рабочего времени, меню, объявления, события, чаты, документы, бесплатные кружки, оплата за сад через загрузку чеков, лист ожидания и аналитика для владельца.

**Первый клиент и демо:** детский сад **Happy Steps**. Название, логотип и акцентный цвет настраиваются для каждого сада; Happy Steps — тема по умолчанию.

**Главный принцип:** максимально просто для родителей и воспитателей, функционально для администрации, информативно для владельца. Каждый экран отвечает на один вопрос. Глаз не перегружен.

**Подписка** (оплата садами за платформу) — последний этап, сейчас только заготовка в БД (раздел 10).

## 3. Арендность, роли и права

### 3.1 Арендность
- Каждый сад — организация (`kindergarten`). Все доменные таблицы содержат `kindergarten_id`.
- Один человек (номер телефона) = один аккаунт. Он может состоять в нескольких садах и иметь несколько ролей в одном саду (например, воспитатель, чей ребёнок ходит в этот же сад). Членство хранится в `memberships (user_id, kindergarten_id, role, status)`.
- Если у пользователя больше одного сада или роли — переключатель в шапке. Последний выбор запоминается.

### 3.2 Роли
| Роль | Код | Кто это |
|---|---|---|
| Суперадмин платформы | `superadmin` | Команда платформы (вы). Вне садов |
| Владелец | `owner` | Собственник сада |
| Заведующая | `head` | Управляет садом ежедневно |
| Администратор/бухгалтер | `accountant` | Оплаты, табель |
| Воспитатель | `teacher` | Привязан к одной или нескольким группам |
| Педагог кружка | `club_teacher` | Ведёт свои кружки |
| Повар | `cook` | Меню, число порций |
| Родитель | `parent` | Привязан к одному или нескольким детям |

### 3.3 Кто кого создаёт и удаляет
- **Владелец:** любые аккаунты своего сада, включая заведующих и бухгалтера. Может архивировать и окончательно удалять.
- **Заведующая:** воспитателей, педагогов кружков, поваров, детей и родителей. Не может создавать/архивировать владельца, других заведующих и бухгалтера.
- Нельзя архивировать последнего владельца сада.
- **Суперадмин:** создаёт сад и его первого владельца.

## 4. Аккаунты и вход

- **Вход:** номер телефона (+7, маска `+7 (___) ___-__-__`) + пароль. Никаких SMS.
- **Создание аккаунта:** администратор вводит ФИО, телефон, роль (и группу/ребёнка) → система создаёт пользователя и **одноразовую ссылку-приглашение** (действует 72 часа) → кнопки «Скопировать» и «Отправить в WhatsApp» (ссылка `wa.me/<номер>?text=...` с готовым текстом на языке сада). По ссылке человек задаёт пароль и входит.
- **Сброс пароля:** только через администрацию. Заведующая/владелец нажимает «Сбросить пароль» в карточке человека → новая одноразовая ссылка, те же кнопки. На экране входа — подсказка «Забыли пароль? Обратитесь к администрации сада».
- **Реализация с Supabase Auth:** создавать пользователей через admin API с `phone` + `phone_confirm: true`, вход через `signInWithPassword({ phone, password })`. Если упрётесь в ограничения — допустимо хранить внутренний технический email вида `<телефон>@users.<домен>` и показывать пользователю только телефон. Решение записать в DECISIONS.md.
- **Пароль:** минимум 8 символов. Ограничение частоты попыток входа.
- **Дубли:** если номер уже есть в системе (например, родитель из другого сада) — не создавать нового пользователя, а добавить членство и показать администратору «Этот человек уже зарегистрирован, добавлен в ваш сад».
- **Архив:** архивированный пользователь не может войти в этот сад, его сессии в саду инвалидируются. Данные (табели, посещаемость, чеки, сообщения) сохраняются. Владелец может восстановить или удалить навсегда (с подтверждением вводом названия).
- Когда все дети родителя в саду архивированы — членство родителя архивируется автоматически.

## 5. Модули

### 5.1 Дети и группы
**Группа:** название, возрастная категория, вместимость, воспитатели (один или несколько), цвет-метка.
**Ребёнок:** ФИО, дата рождения, фото (необязательно), группа, дата поступления, родители (несколько), аллергии и медицинские заметки (текст), ежемесячная сумма оплаты, статус (активен/архив, причина выбытия).
- Заполненность группы = активные дети / вместимость. Превышение вместимости — предупреждение, заведующая может подтвердить.
- **Перевод ребёнка** в другую группу с датой — история посещаемости остаётся привязанной к группе на дату.
- **Перевод всей группы** (например, в сентябре в старшую): массовое действие для заведующей.
- Удалить группу с активными детьми нельзя — сначала перевести.
- Родитель видит только своих детей; у одного родителя может быть несколько детей в разных группах.
- Заведующая может отвязать родителя от ребёнка (например, по решению суда); действие пишется в журнал.

### 5.2 Учёт рабочего времени сотрудников
- **Отметка:** большая кнопка «Начать рабочий день» / «Закончить рабочий день» на главной сотрудника. Без геолокации и QR — на доверии, но все ручные правки видны владельцу.
- **График:** у каждого сотрудника шаблон по дням недели (например, Пн–Пт 08:00–17:00). Заведующая может изменить конкретный день (замена, сокращённый день) и отметить отсутствие: больничный, отпуск, отгул, без причины.
- **Выходные и праздники сада** задаются в настройках (с предзаполнением праздников РК на год); в эти дни отметка не ожидается.
- **Статусы дня** (как на скриншоте-референсе, 4 плитки):
  - **На работе** — отметился вовремя и ещё не ушёл;
  - **Опоздал** — отметился позже начала смены больше чем на порог (настройка, по умолчанию 10 мин);
  - **Отсутствует** — отмечено отсутствие с причиной;
  - **Не отметились** — по графику должен быть, но отметки нет.
- **Крайние случаи:**
  - Забыл закончить день → в конце смены + 2 часа день закрывается автоматически временем окончания смены с флагом «закрыто автоматически»; push сотруднику и видно заведующей.
  - Отметка в выходной по графику → фиксируется как работа вне графика, не опоздание.
  - Повторное нажатие «Начать» после «Закончить» в тот же день → новый интервал (разрыв), время суммируется.
  - Ручная правка времени заведующей → обязательный комментарий, запись в журнал, значок «изменено» в табеле.
- **Табель за месяц:** таблица сотрудник × день с часами и статусами, итог часов, опозданий, пропусков. Экспорт в Excel (.xlsx) и PDF.

### 5.3 Посещаемость детей
- **Отметка:** воспитатель открывает список своей группы на сегодня — у каждого ребёнка переключатель «Был / Не был». Кнопка «Все пришли» для быстрого старта, затем снять отсутствующих.
- **Пропуски от родителей:** родитель в приложении нажимает «Ребёнок не придёт», выбирает дату или период и причину (болеет, отпуск, семейные обстоятельства, другое) + комментарий. Такие дети заранее отмечены у воспитателя как «не придёт — причина», в списке видно иконку.
- Родитель может отменить сообщённый пропуск до начала дня.
- **Напоминание:** если к 10:00 (настройка) группа не отмечена — push воспитателю, после 11:00 — заведующей.
- Правка прошлых дней — только заведующая/владелец, с записью в журнал.
- После пропуска по болезни родителю показывается подсказка загрузить справку в документы (без блокировки).
- **Число порций для повара** = активные дети − сообщённые пропуски на сегодня, после отметки — фактическое число.
- Отчёт посещаемости по группе за месяц (ребёнок × день), экспорт в .xlsx.

### 5.4 Меню на сегодня
- Повар (или заведующая) заполняет меню на конкретный день: приёмы пищи (завтрак, второй завтрак, обед, полдник, ужин — какие включены, настраивается) → блюдо + состав одной строкой.
- Кнопка «Скопировать с другого дня» для скорости.
- Все видят меню на сегодня и на завтра; родитель — на главной.
- У повара на главной: меню, ожидаемое число порций по группам и список детей с аллергиями (ФИО, группа, аллергия).

### 5.5 Объявления
- Публикуют: владелец, заведующая — всему саду, выбранным группам или только сотрудникам; воспитатель — только своим группам.
- Заголовок, текст, до 10 фото, вложения PDF, флаг «Важное» (закреплено сверху, выделено).
- Без комментариев и лайков. У каждого читателя — отметка «прочитано» автоматически при открытии.
- Автор и администрация видят статистику: «прочитали 34 из 52», список непрочитавших с кнопкой «Напомнить» (push).
- Редактирование и удаление — автором и администрацией.

### 5.6 Календарь событий
- События: утренники, родительские собрания, праздники, выходные дни сада, экскурсии. Поля: название, дата/время, место, описание, аудитория (весь сад / группы / сотрудники).
- Вид: список «Ближайшие» на главной + месячный календарь.
- Дни рождения детей и сотрудников автоматически показываются в календаре администрации и воспитателя (родителям — только своих детей).
- Push за день до события аудитории.

### 5.7 Чаты (realtime)
- **Чат группы:** создаётся автоматически для каждой группы; участники — воспитатели группы, заведующая, все родители детей группы. Состав обновляется при переводах и архивации автоматически.
- **Личный чат родитель ↔ сотрудник:** родитель может написать воспитателю своего ребёнка, заведующей, владельцу. Сотрудник может написать любому родителю своего сада.
- **Чат сотрудников:** общий для всех сотрудников сада; плюс личные чаты между сотрудниками.
- **Родитель ↔ родитель лично — нет.**
- Сообщения: текст, фото, файлы (PDF), ответ на сообщение. Счётчики непрочитанных. Индикатор «прочитано» в личных чатах.
- Модерация: заведующая/владелец может удалять сообщения в чате группы; удалённое показывается как «Сообщение удалено администрацией».
- Заведующая может закрыть чат группы «только для объявлений сотрудников» (родители читают, но не пишут).
- **Тихие часы:** в настройках сада (по умолчанию 21:00–08:00) push о сообщениях от родителей сотрудникам не приходят, сообщения ждут утра. Срочное — через звонок, это пишется в подсказке.

### 5.8 Документы
**Документы детей** — простое хранилище, без статусов.
- Папка ребёнка с категориями: медицинские справки, прививки, заявления и договоры, другое.
- Загружают: родители и администрация. Видят: родители этого ребёнка, заведующая, владелец, воспитатель группы (только просмотр).
- Форматы: JPG, PNG, HEIC (конвертировать в JPEG), PDF; до 15 МБ на файл. С телефона — прямо с камеры.

**Документы сотрудников** — со сроками.
- Типы: медкнижка, справка о несудимости, договор, другое. У каждого — дата окончания (необязательно).
- Загружают сам сотрудник или администрация.
- За 30 и 7 дней до окончания — push сотруднику и заведующей; на дашборде владельца — карточка «Истекающие документы».

### 5.9 Оплата за сад (чеки)
Онлайн-оплаты нет. Деньги идут на счёт сада вне приложения, приложение подтверждает факт оплаты.
- **Начисление:** 1-го числа каждого месяца автоматически создаётся счёт на каждого активного ребёнка = его ежемесячная сумма. Бухгалтер может скорректировать сумму конкретного счёта (скидка, перерасчёт) с обязательным комментарием.
- **Реквизиты** сада (Kaspi-номер, IBAN, получатель, назначение платежа) задаются в настройках и показываются родителю рядом с суммой, с кнопкой «Скопировать».
- **Родитель:** видит сумму к оплате, срок, статус; нажимает «Загрузить чек» → фото/скриншот/PDF → статус **«На проверке»**.
- **Бухгалтер/владелец:** очередь чеков «На проверке» → открыть чек, указать подтверждённую сумму → **«Оплачено»** или **«Отклонено»** с причиной (родитель получает push и может загрузить заново).
- Частичная оплата: остаток долга переносится; переплата — в аванс на следующий месяц.
- Статусы счёта: Не оплачен → На проверке → Оплачен / Частично / Отклонён. Просрочен — после срока оплаты (настройка, по умолчанию 10-е число).
- Валюта — тенге (₸), формат `45 000 ₸`.
- Архивация ребёнка не удаляет его долги — они остаются видны в финансах.
- **Кружки бесплатные** и в оплате не участвуют.

### 5.10 Кружки и курсы (бесплатные)
- Каталог: название, описание, фото, педагог, возраст (от–до), расписание (дни/время), место, лимит мест.
- Родитель видит только кружки, подходящие по возрасту его ребёнку, нажимает «Записаться» → заявка.
- Заведующая или педагог кружка подтверждает/отклоняет. Мест нет → ребёнок автоматически встаёт в очередь кружка, при освобождении места заведующей приходит уведомление.
- Родитель может отписать ребёнка; администрация может исключить.
- Педагог кружка видит списки своих кружков с контактами родителей и может писать им в чат.

### 5.11 Лист ожидания (приём новых детей)
- У каждого сада есть **публичная форма заявки** (без входа, по ссылке/QR): ФИО ребёнка, дата рождения, ФИО родителя, телефон, желаемая дата поступления, комментарий. Защита от спама (honeypot + ограничение частоты).
- Администрация может добавить заявку вручную.
- Статусы: Новая → Связались → Принята / Отказались. Комментарии к заявке.
- **«Принять»** в один клик создаёт карточку ребёнка (с выбором группы) и аккаунт родителя с приглашением.
- На дашборде: «N детей ожидают», последние заявки со статусами (как на референсе).

### 5.12 Уведомления
- **Push (Web Push) + колокольчик в приложении** с историей. Других каналов нет.
- Пользователь в профиле включает/выключает типы уведомлений.
- События, которые уведомляют: новое сообщение, новое объявление, напоминание о событии, пропуск ребёнка (воспитателю), группа не отмечена, чек отклонён/принят, новый чек на проверку (бухгалтеру), заявка в кружок, новая заявка в лист ожидания, истекающий документ, день закрыт автоматически.
- На iOS push работает только в установленной PWA — показывать родителю понятную инструкцию «Добавьте на экран Домой» при первом входе с iPhone.

### 5.13 Журнал действий
Все чувствительные действия пишутся в журнал: создание/архивация/удаление аккаунтов, сброс пароля, правки табеля и посещаемости задним числом, подтверждение/отклонение чеков, изменение сумм, удаление сообщений, отвязка родителя. Владелец видит журнал с фильтрами.

## 6. Главная (дашборд) по ролям

Референс — прикреплённый скриншот (Kindy): белые карточки на светлом фоне, крупные цифры, кольцевые индикаторы, пастельные плитки статусов, правая колонка с новостями и листом ожидания. Наша версия — в палитре Happy Steps (раздел 8).

**Владелец / заведующая (десктоп — сетка карточек, телефон — одна колонка):**
1. Верхний ряд: **Дети** (N активных) · **Группы** (N, кольцо заполненности %) · **Посещаемость сегодня** (пришли / отсутствуют, кольцо) · у владельца ещё **Оплаты месяца** (оплачено % от начисленного, сумма долгов).
2. **Учёт рабочего времени**: 4 плитки — На работе / Опоздал / Отсутствует / Не отметились, ссылка «Список сотрудников».
3. **Меню на сегодня** и **Ближайшие события**.
4. Правая колонка: **Важные объявления**, **Лист ожидания** (N ожидают, последние заявки), **Требует внимания** (группы не отмечены, чеки на проверке, заявки в кружки, истекающие документы).
Каждая карточка кликабельна и ведёт в соответствующий раздел.

**Воспитатель:** кнопка рабочего дня · моя группа сегодня (отмечено/нет, кто не придёт и почему, кнопка «Отметить») · меню · чат группы (непрочитанные) · дни рождения недели · события.

**Родитель (телефон в приоритете):** карточка ребёнка (если детей несколько — свайп/переключатель): был ли сегодня в саду · «Ребёнок не придёт» · меню на сегодня · важные объявления · оплата (сумма, статус, «Загрузить чек») · ближайшие события · мои кружки.

**Повар:** меню на сегодня/завтра · число порций по группам · дети с аллергиями.

**Бухгалтер:** чеки на проверке · должники · начислено/оплачено за месяц · табель.

**Педагог кружка:** кнопка рабочего дня · мои кружки и заявки · чаты.

## 7. Аналитика владельца

Отдельный раздел «Аналитика» с выбором периода (неделя, месяц, квартал, год, произвольный) и сравнением с предыдущим периодом (▲▼ %).

1. **Посещаемость и заполненность:** средняя посещаемость по дням (линия), по группам (столбцы), заполненность групп (%), заболеваемость (доля пропусков по причине «болеет»), топ групп по пропускам.
2. **Дисциплина сотрудников:** опоздания и пропуски по сотрудникам, отработанные часы vs по графику, число автоматически закрытых дней, ручные правки.
3. **Финансы:** начислено / оплачено / долг по месяцам, процент собираемости, список должников с суммой и сроком, средний срок между началом месяца и оплатой.
4. **Воронка и отток:** заявки в лист ожидания → связались → приняты, конверсия; новые дети и выбывшие за период, причины выбытия; динамика числа активных детей.

Каждый график — с кратким выводом сверху одной строкой (например, «Посещаемость в октябре 87%, на 4% выше сентября»). Экспорт каждой таблицы в .xlsx.

## 8. Дизайн и UX

### Бренд Happy Steps
- **Цвета:** малиновый (акцент, кнопки, активные элементы — ориентир `#D6336C`, подобрать спокойный оттенок), белый (основной фон карточек), голубой (вторичный акцент и фоны — ориентир `#4FA3E0` и светлый `#EAF5FD`). Нейтральные серые для текста. Пастельные оттенки для плиток статусов (зелёно-голубой «на работе», кремовый «опоздал», розовый «отсутствует», лавандовый «не отметились»).
- Акцентный цвет и логотип настраиваются у каждого сада; дизайн-токены через CSS-переменные.
- **Шрифт** с полной поддержкой казахской кириллицы (ә ғ қ ң ө ұ ү һ і): например, Manrope или Inter. Проверить рендер казахских букв на скриншотах.
- Светлая тема обязательна; тёмная — по желанию, если не усложняет.

### Принципы «не перегружать глаз»
- Много белого пространства, скругления 16–20px, мягкие тени.
- Не больше одного яркого акцента на карточку. Красный только для ошибок и долгов.
- Одно главное действие на экран, крупная кнопка.
- Цифры крупно, подписи мелко (как на референсе).
- Пустые состояния с дружелюбной иллюстрацией/иконкой и подсказкой, что сделать.
- Скелетоны при загрузке, понятные сообщения об ошибках на языке пользователя.

### Навигация
- **Телефон:** нижняя панель из 4–5 пунктов по роли (например, родитель: Главная · Чаты · Оплата · Ещё).
- **Десктоп:** боковое меню + шапка (поиск, язык, чаты, уведомления, аккаунт) как на референсе.
- Сенсорные элементы ≥ 44px. Контраст текста по WCAG AA.

### Языки
- Русский (по умолчанию) и казахский. Язык выбирает пользователь; язык сада по умолчанию — в настройках.
- Все строки в файлах переводов, никаких захардкоженных текстов. Корректные плюральные формы.
- Пользовательский контент (объявления, меню) не переводится.

### Время и формат
- Часовой пояс сада в настройках, по умолчанию `Asia/Almaty` (Казахстан с 2024 года — UTC+5). Все «сегодня», напоминания и автозакрытия считаются в часовом поясе сада.
- Даты `12.10.2026`, время 24-часовое.

### Офлайн
- PWA кэширует оболочку и последние просмотренные данные. Без сети — баннер «Нет подключения», данные только для просмотра, действия блокируются с понятным сообщением.

## 13. Ключевые сценарии (e2e-тесты обязательны)

1. Суперадмин создаёт сад → владелец по ссылке задаёт пароль → создаёт заведующую → заведующая создаёт группу, воспитателя, ребёнка и родителя → родитель входит по ссылке и видит своего ребёнка.
2. Воспитатель начинает рабочий день с опозданием → у заведующей плитка «Опоздал» +1.
3. Родитель сообщает «болеет» на 3 дня → у воспитателя ребёнок помечен, у повара порций на 1 меньше.
4. Воспитатель отмечает посещаемость → у родителя на главной «Сегодня в саду» → у владельца обновилась посещаемость.
5. Родитель загружает чек → бухгалтер отклоняет с причиной → родитель получает уведомление и загружает новый → бухгалтер подтверждает → счёт «Оплачен», долг исчез из аналитики.
6. Родитель записывает ребёнка в полный кружок → ребёнок в очереди → место освободилось → заведующая подтверждает.
7. Заявка через публичную форму → «Принять» → появились ребёнок и родитель с приглашением.
8. Сообщение в чате группы приходит родителю в realtime; родитель не может написать другому родителю лично.
9. Владелец архивирует воспитателя → тот не может войти, его табель за прошлые месяцы на месте.
10. Изоляция: пользователь сада A не видит ни одной записи сада B (через UI и прямые запросы к API).
11. Сотрудник с ролью родителя в том же саду переключается между ролями.
12. Смена языка на казахский — все экраны текущей роли без русских строк.

## 14. Не входит в эту версию (позже)

Онлайн-оплата (Kaspi, эквайринг) и биллинг подписки; нативные приложения; SMS и WhatsApp-рассылки; Telegram-бот; отметка по QR/геолокации; дневник ребёнка (сон, еда, настроение); доверенные лица для забора ребёнка; посты родителей в ленте, лайки и комментарии; посещаемость занятий кружков; несколько филиалов у одного владельца со сводной аналитикой; циклическое меню и технологические карты.
